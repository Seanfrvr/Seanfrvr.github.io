EXHIBIT 01A // DNS PERIODICITY

BLACK SIGNAL asks whether repeated DNS requests that look ordinary individually become interesting when viewed as behaviour over time. The clean sequence clustered tightly around ten seconds, while later retry-like traffic was treated separately instead of being forced into a fake perfect beacon narrative.

PACKET VIEWRepeated DNS requests to the same lab-only domain were visible in the preserved capture.
TIMINGTShark quantified the clean ~10 second interval sequence.
CORRELATIONZeek independently reconstructed the same periodic behaviour.
DETECTIONThe active Suricata ruleset produced no meaningful alert for that behavioural pattern.
NOT PROVEN: malware, compromise, data exfiltration, or confirmed DNS command-and-control.
OPEN ANALYST NOTE ↓
The important lesson is behavioural: one DNS query is ordinary. Repeated requests to the same destination with tightly grouped timing create a different analytical object. The case deliberately separates observable periodicity from claims of malicious intent.

EXHIBIT 02A // JITTERED TLS CALLBACK-LIKE ACTIVITY

GHOST CHANNEL removes plaintext application visibility and adds deliberate timing jitter. Six separate TLS sessions shared the same source, destination service, SNI and TLS characteristics, with intervals varying between roughly seven and fifteen seconds.

IDENTITYSix ClientHello observations advertised the same SNI.
TIMINGRepeated sessions showed bounded but variable spacing rather than fixed periodicity.
METADATAEncryption hid application content, not endpoints, timing, SNI or TLS session characteristics.
CORRELATIONZeek independently reproduced the same SNI and timing sequence.
ASSESSMENT: callback-like encrypted behaviour worth investigation. NOT confirmed command-and-control.
OPEN ANALYST NOTE ↓
This case exists to show that defenders can still hunt encrypted activity through metadata and behaviour. The analyst has to stop where the evidence stops: repeated TLS identity plus timing is useful evidence, but encrypted payload meaning remains unknown.

Packets provide the evidence.
TraceHound surfaces the leads.

After completing the investigations manually, I built TraceHound in Python with Scapy to automate repetitive first-pass PCAP work: protocol summaries, conversation ranking, TCP response triage, repeated-session timing, DNS periodicity, TLS SNI correlation, HTTP path review and consolidated analyst leads.

The design deliberately avoids output such as “C2 confirmed”, “malware detected” or “host compromised” when packet structure alone cannot support those conclusions.
